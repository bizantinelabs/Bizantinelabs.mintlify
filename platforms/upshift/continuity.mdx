## Independence matrix

| Property | Independent of Upshift/August? |
| --- | --- |
| Read state | Yes (RPC) |
| Compute NAV | Partial — requires oracle set |
| Routine strategy actions | **No** — needs August policy engine path |
| Process withdrawals | No — operator processing beyond buffer |
| Pause | Yes (Owner multisig, co-signed with Upshift) |
| Emergency exit (pull to vault) | Yes (Owner multisig, co-signed) |
| Replace operator | Yes (Owner multisig, co-signed) |
| Migrate assets | Co-signed with Upshift |
| Wind down | Likely requires platform cooperation |

## Failure modes

- August API / policy engine unavailable → routine strategy actions block; funds remain on chain
- Upshift service unavailable → co-signed emergency paths still executable if partner multisig operational
- Partner multisig unresponsive → escalate per [Incident response](/security/incident-response); position may be trapped until multisig activity resumes

## Migration

Migration to a Direct SleeveVault is possible via co-signed Owner-multisig action to pull-to-vault and transfer assets to a Bizantine-controlled address. Migration plan is generated by `connector.getMigrationPlan(vault)`.
